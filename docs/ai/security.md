# AI security and privacy

This page covers the Gemini cost estimator, the Markdown reference files and the Gemini file registry. Routing-service security is in [Backend security](../backend/security.md#integrations).

## Requirements

| Area | Requirement |
|---|---|
| Data sent to Gemini | Structured context only, with content filtering. This includes journey details and fleet cost inputs, as listed in [Inputs, outputs and model](index.md#inputs-outputs-and-model). Only the minimum context required for the estimate is shared. |
| Gemini API key | Stored as a server-side secret, fetched only by authorised backend services and never sent to the client. |
| Private cost data | Fleet cost settings are high-sensitivity data and remain organisation-scoped. How this data is handled when used by Gemini is not detailed in the project material. |
| Model-version traceability | The model version should be recorded with cost-prediction inputs and outputs. How it is recorded is not documented. |
| Failure behaviour | If a re-upload of a reference file fails, the backend reports the failure and does not use an invalid reference. |

## Threats

| Threat | Component | Required control |
|---|---|---|
| Incorrect cost calculation | Cost assessment | Validated inputs, transparent assumptions, independently verified calculation tests |
| Exposure of private cost information | Cost assessment, database | Organisation isolation, authorization, minimum necessary exposure |
| Private data reaching a third party beyond what the estimate needs | Gemini integration | Structured context only, content filtering, minimum necessary data |

## Boundaries of the output

- The estimate is decision support. The Fleet Manager decides.
- Cost results are meant to be deterministic and independently verifiable, while the explanation is generated by a model. The estimate must not be presented as a guaranteed cost or profit.
- Reference data is historical and partial.
